# libSceSysmodule

## change [sceSysmoduleIsLoaded, sceSysmoduleLoadModule, sceSysmoduleUnloadModule]

- [sceSysmoduleIsLoaded, sceSysmoduleLoadModule, sceSysmoduleUnloadModule](../../../core/libs/prx/libSceSysmodule/Export.cpp) (libSceSysmodule) accept, in a PS5 process, the 141 ids `sceSysmoduleIsLoaded` did not reject in a payload process on a PS5 (firmware 13.60) and return `0x805A1000` for every other id, as the console does; that includes 51 ids the module table names from older firmware, such as 0x0001 (`libSceAudioOut`) and 0x0080 (`libSceJson`). Load and unload are counted as measured. The 21 accepted ids the table does not name (0x0111, 0x0117, 0x011c to 0x011f, 0x0121 to 0x0124, 0x0129, 0x012c to 0x012e, 0x0133, 0x0134, 0x0136 and 0x013a to 0x013d) are logged and return 0 without loading anything, so `sceSysmoduleIsLoaded` reports them as loaded; which module each loads is not known. Loading id 0x00ff ended the payload process. One title (PPSA04354) calls `sceSysmoduleIsLoaded` with id 0x96 at twelve sites and loads it only when the result is 0x805a1001; any other result lets it continue. In a PS4 process (`sceKernelIsPs4Process`, a `CUSA` title ID) they accept every id the module table names instead, as PS4 titles and their bundled modules load ids a PS5 rejects: `libSceFios2` of CUSA01715 loads 0x00d7 (`libSceDiscMap`) and stops when that fails; which of these ids a PS4 accepts has not been measured.
