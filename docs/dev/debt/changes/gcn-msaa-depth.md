# libSceAgcDriver

## add Functional

- [PS4 (GCN) multisampled depth targets](../../../core/libs/prx/libSceAgcDriver/Graphics/src/DepthSurface.cpp) (libSceAgcDriver, PS4) - not checked on a console. DB_Z_INFO and DB_STENCIL_INFO `TILE_MODE_INDEX` (bits 20-22) select the 2D depth tile modes 0-4 of the depth and stencil planes, and a plane's footprint and initial contents follow addrlib's macro tiling with the fragments of a pixel interleaved (depth sample order). Array slices, the PRT depth modes and depth targets with mip levels throw. The HTILE is only read whole: on a PS4 a word with ZMask (bits 0-3) 0 proves its tile cleared to DB_DEPTH_CLEAR whatever its minimum and maximum Z, as the DB reads it (the PS4 has no TC-compatible HTILE, so no texture reads the word), and a separate stencil plane that holds one byte value starts the host stencil at that value instead of DB_STENCIL_CLEAR. A T# may view the plane at its own width and height inside the DB extent, which the DB pads to whole macro tiles (1920x1080 in a 1920x1152 target); multisampled reads fetch texels, so the padded host image serves them, and sample 0 is copied out at the T# extent. A T# cannot carry HTILE on a PS4, so a depth plane sampled before an in-place expand is read from the host image, which already holds the decompressed depth, where the console would read the uncompressed plane memory; the existing `[gpu] native multisample depth ... sampled through a descriptor without metadata before an in-place expand` line still reports it.
- [PS4 multisampled stencil read as UNORM](../../../core/libs/prx/libSceAgcDriver/Graphics/src/DepthSurface.cpp) (libSceAgcDriver, PS4) - a 2D MSAA T# of `8_UNORM` (format 1) over the stencil plane reads the host stencil through a copy: the recorder is synchronized, the samples are read back to a buffer and drawn into an R8 multisampled color image viewed as UNORM. The copy is refreshed when the stencil was written since the last copy or is the bound attachment, so each refresh stalls the CPU for one submission.
- [PS4 multisampled color textures](../../../core/libs/prx/libSceAgcDriver/Graphics/src/MultisampleTarget.cpp) (libSceAgcDriver, PS4) - a 2D MSAA T# over a 2D-thin or 2D-display surface no draw rendered to takes the T# pitch and the height rounded up to the single-sample macro tile as its extent, the extent the CB gives the same surface, and reads its contents with the multisampled GCN layout. When a draw then binds the same surface in another format (a red/blue swap or a reinterpretation), the target the texture created is retired, as it only mirrored guest memory, and the draw imports the memory again. Sample 0 of a target is copied at the T# extent and in the T# format, through a reinterpreting copy when the formats differ.
- [Two-component color component swaps](../../../core/libs/prx/libSceAgcDriver/Graphics/src/State.cpp) (libSceAgcDriver) - CB_COLOR_INFO COMP_SWAP 2 (STD_REV) and 3 (ALT_REV) of the 8_8 and 16_16 formats export Y to red and X to green, and W to red and X to green, the two-component swaps of Mesa's `si_translate_colorswap`; not measured on a console.
- [Occlusion counter dumps on a PS4](../../../core/libs/prx/libSceAgcDriver/Execution/src/Pm4.cpp) (libSceAgcDriver, PS4) - a PIXEL_PIPE_STAT_DUMP writes 8 DB blocks on a PS4, which has 8 render backends, instead of the PS5's 16, each 16 bytes apart with the whole count in the first block. EVENT_WRITE PIXEL_PIPE_STAT_CONTROL (event 0x38, index 1) is accepted only when it selects counter 0, a 128-bit stride and every DB (`0x7fc00` on a PS4, read with the field layout of AMD PAL's gfx6 headers) and is otherwise refused; it changes nothing, as that is the layout the dumps already use.
- [Primitive restart on a PS4](../../../core/libs/prx/libSceAgcDriver/Graphics/src/State.cpp) (libSceAgcDriver, PS4) - restart is enabled by VGT_MULTI_PRIM_IB_RESET_EN, context register 0x2a5 bit 0 on the PS4's CI GPU, as well as by the PS5's user-config register 0x24b; not measured on a console.
- [SET_PREDICATION on a PS4](../../../core/libs/prx/libSceAgcDriver/Execution/src/Pm4.cpp) (libSceAgcDriver, PS4) - the packet has two payload words, the address bits 31:0 and then the properties with address bits 39:32 in bits 0-7, as Mesa's radeonsi emits it for gfx6 to gfx8; the PS5 form has three.

# shader

## add Functional

- [Unnormalized depth comparison](../../../core/shader/recompiler/SpirvBackend/src/SpirvImageEmitter.cpp) (shader) - Vulkan rejects comparison through an unnormalized sampler, so a guest sampler with forced unnormalized coordinates that only samples with depth comparison at an implicit LOD or LOD 0, over one 2D layer, is created normalized on the host and the shader divides the coordinates by the size of the base level and samples level 0 (`UnnormalizedCompareBase`). An implicit LOD the console would compute above 0 is not reproduced, and a texel offset, a nonzero explicit LOD or an array, cube or 3D image still throws.
